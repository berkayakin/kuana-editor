# CLAUDE.md

Guidance for working on **Kuana**, a fast, GPU-rendered code editor written in Rust on
[GPUI](https://www.gpui.rs) (Zed's UI framework). Kuana was called "Forge" early on, then
"Kin" (up to 0.1.6); the package, binary (`kuana`), bundle id (`dev.kuana.editor`) and config folder are now
`kuana` (`theme::move_legacy_config` moves an existing `kin` config folder over on first start); the GitHub
repository is `berkayakin/kuana-editor`.
User-facing docs live in `README.md` (the pitch) and `docs/` (the reference); this file is about how the code works and how to
change it safely.

## Commands

```bash
cargo build --release            # binary: target/release/kuana (needs cmake, for wasmtime)
cargo run --release -- <folder> [<file>…]
cargo build                      # debug build: optimized dependencies, quick to rebuild Kuana itself
cargo test                       # unit tests (lint rules, search, git, themes, document)
cargo clippy --all-targets       # must be clean: CI (.github/workflows/ci.yml) fails on any warning
cargo bundle --release           # macOS .app (needs `cargo install cargo-bundle`)
scripts/screenshot.sh [<folder> [<file>…]]  # README screenshots → docs/screenshots (macOS; -h for options)
scripts/record.sh [<script>]     # plays scripts/readme.autopilot and saves docs/screenshots/demo.webp (macOS, img2webp)
scripts/smoke.sh <kuana> <folder> <out>  # CI's smoke test: plays scripts/smoke.autopilot, fails on errors/panics
```

- Rust 1.94 (edition 2024). oxc crates are pinned to **0.139**; newer ones need Rust 1.97.
  tree-sitter is **0.26** with its `wasm` feature (wasmtime 36 LTS); 0.27's wasmtime 48 needs Rust 1.95.
- GPUI is used with the `runtime_shaders` feature because this machine's Xcode has no Metal
  toolchain; shaders compile at launch instead of build time.
- The first build of gpui/rumdl/tree-sitter is slow (minutes); incremental builds are seconds.
- Keep the build warning-free, clippy included (lints that flag intended code are allowed in `Cargo.toml`'s `[lints.clippy]`).

## Architecture

Everything is one binary crate. The window's root view is `Workspace`; every open file is an
`Entity<Editor>` owning a `Document`.

| File | Role |
| --- | --- |
| `main.rs` | App setup: fonts, theme, keymap, menus (`menus_for(mac)`), window, CLI paths / restore last project. macOS: `limit_window_zoom` adds `sendEvent:` to GPUI's window classes so double clicks in the title bar strip go to GPUI's view, not AppKit (which zoomed on buttons too, and with Kuana's drag areas cancelled out). Window dragging: `title_bar::window_drag_area` marks the chrome's free space (the title bar's empty parts, after the tabs of the strips along the top, the diff view's strip, the status bar's middle): a press drags (macOS `performWindowDragWithEvent`; Windows an occluded Drag area, so drops meant for what's behind go on it), a double click zooms. Only free space: a press reaches every element under the pointer, so one behind tabs would move the window too |
| `workspace.rs` | Root view: title bar (sharing the top row with the tabs), activity bar, sidebar (file tree / Git), panes (`Pane`: tabs + active; flat row or column with share sizes; `self.tabs` lists every editor), tab bars with drag & drop and pinning, find bar, problems panel, status bar, modals, toasts, context menu, file operations, Git orchestration |
| `editor.rs` | Editor view + custom GPUI `Element` that shapes and paints only visible lines; multi-cursor editing, IME (`EntityInputHandler`), mouse, search highlights, bracket matching, git gutter/blame, hunk popover; right-click emits `EditorContextMenu` (the workspace builds the menu). Modes: `Full`, `SingleLine` (inputs), `MultiLine` (commit message) |
| `wrap.rs` | Soft wrap `WrapMap`: per-line breaks (GPUI's `LineWrapper`, continuation indent), folds (zero rows) and block rows (`set_blocks`: rows above a line that aren't text, e.g. an opened Git hunk's deleted lines from `Editor::block_rows`; `block_at`; `line_of` maps them to the line above, `vertical_target` steps over them). `row_starts[line]` is where a line's blocks start; `first_display_row` is its text. The editor works in *display rows*; call `sync_wrap` before mapping offsets to rows (it keeps the line at the top in place as rows above it change: lenses arriving, folds, a new width, a reload's lines above). A break also records where its row starts in the buffer (`Break::from`, a `Resume`), so a long line's rows on screen are built alone (`DisplayLine::window`); `WrapMap::generation()` changes when rows do (marker caches key on it); blocks are an `Arc` (`set_blocks` is O(1) for the same one) |
| `document.rs` | `ropey` buffer, multi-range edits, undo/redo transactions (none in a `read_only` document, the Merge view's sides), save/reload (a reload is read and diffed in the background and applied as an undoable edit, see Parsing), disk mtime tracking (`changed_on_disk`: auto-save skips such files, Save asks first through `Workspace::confirm_overwrite`: Overwrite, Reload = `revert`, one undoable edit over the unsaved text, or Cancel; `Workspace::save_tabs` for Run, Debug, `:wa` and Save All on close skips them with a toast), diagnostics storage (built-in + external merged; `diagnostics_generation`, per-severity counts `severity_count`/`has_errors`). | `lsp/` | Language servers. `rpc.rs` JSON-RPC over stdio (reader/writer threads; a `Request` future per request, which sends `$/cancelRequest` when dropped unanswered, so keep it alive to wait; unanswered after `REQUEST_TIMEOUT` (120 s) the writer thread fails it with `TIMED_OUT`; `RpcError` keeps the code, `is_cancelled` = ContentModified/RequestCancelled/ServerCancelled, never toasted; stderr through `for_each_line`, as bytes, so a non-UTF-8 line can't stop the draining; `Client::stop(wait)` = shutdown, exit, then kill); PHP: phpactor first where `usable`, i.e. PHP is on PATH, except on Windows, as in Zed), discovery (project's `node_modules`/venv, then PATH, then Kuana's own copies; augmented PATH; a broken rustup `rust-analyzer` proxy is skipped); `path_with(node_bin)` puts it on servers' PATH), `go install`; `ACTIVE` installs, the `ServersInstalled` global makes every workspace `retry_missing`; `check_for_update` (weekly, after starting a Kuana-installed server); `mod.rs` `LspStore` entity per workspace: starts servers per (server, root), syncs documents, routes diagnostics/progress/applyEdit (`$/progress` redraws at most every `PROGRESS_THROTTLE`, 100 ms, per token, the latest shown by a trailing `progress_redraw`; pull diagnostics: `pull` (after `didOpen`, `pull_soon` after edits (`PULL_DELAY`; via `cx.defer` from `Editor::edited`, and `send_edits`), other open files of an `interFileDependencies` server after `PULL_OTHERS_DELAY`, all on `workspace/diagnostic/refresh`) for a server with `diagnosticProvider` or a dynamic `textDocument/diagnostic` registration (`pull_registrations`, pyright/ESLint; `did_rename` from `Workspace::moved` (undo included); a publish reaches only its own server's list (`Editor::set_server_diagnostics`, read in `Document::text_at_lsp_version` and moved by `diagnostics_since`), a stopped server's go (`forget_diagnostics`); code actions get a server's own diagnostics from `published`; the app's quit stops every server still running within `QUIT_WAIT` (`stop_all_for_quit`, from a quit hook the store registers); a window's servers stop with it (`Drop for LspStore` → `shutdown_all`: shutdown and exit, so a server ends its own helpers, as on a project change); | `editor/lsp.rs` | Editor side: sync (`Document` records `LspChanges` in `raw_replace`; `Editor::edited` sends them), completion menu (lists converted, user snippets included, and ranked on the background executor; a newer ranking cancels an older one (`completion_cancel`/`rank_cancel` via `renew`; the menu's `ranked_for`), and `finish_ranking` ranks at once only when ↑/↓/Enter/Tab comes before it's done; `rank_completions`: items starting with what's typed by exact match, then the server's `sortText`; other fuzzy matches after; ties by label (`CompletionItem::sort_label`, lowercased once); the server's `preselect` among the best; only the best `MAX_MATCHES` (1000) are sorted, `select_nth_unstable`). ## Conventions and patterns

- **Offsets are UTF-8 byte offsets** everywhere (rope, tree-sitter, oxc, diagnostics, git
  hunks use rows). Convert to UTF-16 only at the IME boundary and to chars only for UI.
- **Cached views:** the workspace draws editors, terminals, the Git panel/log and the debug panel through
  `cached(&entity)` (`AnyView::cached`), so they keep last frame's layout until they notify. Anything such a view
  draws must reach it through a method that calls `cx.notify()` on *it*; focus changes and theme/font switches
  (`cx.refresh_windows()`) redraw everything anyway. A cached view fills its parent (`size_full`).
  The root render reads no entity that notifies often: GPUI redraws a window whenever an entity read during its
  last draw notifies, cached or not. So the run widget reads `Workspace::running` / `debug_active` (from
  `TerminalPanelEvent::RunsChanged` and debug events), and tab strips read `tab_looks` (a `TabLook` per tab: title,
  icon, dirty, errors; updated in `tab_changed`), not the terminals and documents themselves.
- **Documents are entities:** `Editor::doc` is an `Entity<Document>` (read `doc.read(cx)`, change through
  `change_doc` for text, `doc.as_mut(cx)` otherwise; both notify). Several editors can show one document
  (`Editor::view_of`, Split Right/Down): each observes it (`document_changed`) and moves its carets through
  `Document::patches_since(seen version)`; a whole new document (an unloaded tab read its file, same entity via
  `Entity::write`) rebuilds the editor. Per-document things (LSP registration, breakpoints, unsaved changes) go
  through one tab; the workspace's `siblings` / `load_tab` / `remove_tab` hand them over.
- **Derived data:** whole-document data an editor draws (outline, fold regions, run targets, conflicts, the
  Markdown preview) lives in `editor/derived.rs`'s `Derived<K, T>`: `shown_*` (drawing) schedules a background
  computation from a rope/tree clone and returns the last value, maybe stale; plain accessors (actions) use `now()`.
  Key by `doc.tree_version()` when the value comes from the syntax tree (it changes when a background parse lands).
- **Per-frame work** is bounded by what's on screen, whatever the document holds: sorted lists are binary-searched
  to the visible range (`selections_touching`, diagnostics through `Reach`, search matches), document-wide data is
  cached by generation counters (`diagnostics_generation`, `code_lens_generation`, `WrapMap::generation`:
  `cached_blocks`, `row_problems`, `editor/markers.rs`), a long line is built only for its rows on screen
  (`DisplayLine::window`, `display_part`), and the caret blink stops on blur and in an inactive window.
  `editor::frame_tests` checks it with 10k carets, 200k matches and a 1.6 MB line;
  `cargo test bench_frames -- --ignored --nocapture` times it (a plain file ~100–170 µs a frame in the dev profile).
- **Parsing:** an edit parses within `PARSE_BUDGET` (1 ms; `OPEN_PARSE_BUDGET` 10 ms on open/reload), then the
  editor's `schedule_parse` finishes it in the background (`Document::parse_job` / `finish_parse`, which replays
  edits made meanwhile). Until then `doc.syntax()` is the old tree, edited. Positions that follow edits (folds,
  breakpoints, the debug line, snippet stops, inlays, lenses, diagnostics) move once per transaction via `Patch`
  (`shift_tracked`, which also gets the text before, so `shift_line` knows a deleted line from one whose text
  above went); `Document::line_edits_since` lets soft wrap re-measure only changed lines. A reload from disk is
  read, decoded and diffed in the background (`Document::reload_job`, keyed by document id, version and the mtime it
  knew; `Editor::reload_if_changed` runs it, `Workspace::reload_documents` asks each document once) and applied as
  one undoable transaction (`apply_reload` → `take_changes`; dropped if the text changed, was saved or got unsaved
  edits meanwhile; past `ONE_BY_ONE` (changes × trees > 2000) one replacement whose patch and line edits still go by
  change): `changed_ranges` diffs the old and new text by line (changed lines
  paired up and narrowed to the bytes that differ), so things on unchanged lines, other editors' carets
  (`patches_since`) and the view's top line (`Editor::reloaded_top`) follow; the editor then sends the changes
  (`edited`) and a didSave (rust-analyzer re-runs cargo check). Lines over `wrap::LONG_LINE` always break into segments: rows with soft wrap, else side by side on the line's one row (`WrapMap::side_by_side`; a break's `indent` is its column), only those in view drawn (`Editor::shown_segments`).
- **Language servers:** a document has a list of servers (`servers::specs`: Kuana's, then extensions'); requests go to
  `Editor::lsp_server_with(capability)`, completion and code actions to all (`lsp_servers`). Per-server config is
  `servers::config` (defaults by program < extension < user `lsp.<id>`, dotted keys expanded). A started server has a
  generation (`LspStore::generations`); anything a task or listener does checks it. Tests use `lsp::fake_server`.
- **Debug adapters:** `debugger::launch::DebugAdapter` (built-ins + `ExtensionAdapter`), found by id/alias with
  `find_adapter`; `DebugSpec::Config` runs a configuration as written (from `project_configurations`).
- **Background work:** `cx.spawn(async move |this, cx| …)` + `cx.background_executor().spawn(…)`;
  on completion check `doc.version()` (or a request id) before applying results. Linting,
  diffing, blame, Git status, reloads from disk, watcher batches, the file tree's folder reads, completion
  ranking and searches all follow this.
- **Text fields are editors:** inputs use `Editor::single_line` / `multi_line` (no bracket or quote pairing there). Structural keys
  (Enter, Esc, ↑/↓, Tab, ⌘↩ `Submit`) call `cx.propagate()` in chromeless modes so the parent
  view (picker, find bar, dialog) handles them via `on_action`.
- **Modals:** add a variant to `Modal` in `workspace.rs`, create the entity, open it with
  `self.modals.open(Modal::X(entity), subscription)` (the `subscribe_in` lives as long as the modal), render in
  `render_modal`, close with `close_modal` (which also refocuses the editor and reverts an unconfirmed theme preview).
- **Workspace layout:** `workspace.rs` is the core (types, the struct, opening tabs); each area is an
  `impl Workspace` in `src/workspace/*.rs`. Panels with their own state are entities: `ProblemsPanel`
  (`problems_panel.rs`), `ProjectTree` (`project_tree.rs`), `TerminalPanel` (`workspace/terminal_panel.rs`), the Git
  panel and log; each reports through an event enum and is told what it shows by setters. The bottom area shows one
  `BottomPanel` (`shows` / `toggle_bottom` / `hide_bottom`).
- **Settings:** add a field to `Settings` or `EditorSettings`, its name to `TOP_LEVEL_KEYS`/`EDITOR_KEYS`
  (and `project_settings::PROJECT_KEYS` if a project may set it; read it through `Settings::at(path)` then)
  (unknown keys are reported), a commented line in `SETTINGS_TEMPLATE`, a row in `docs/settings.md`, and a
  `Setting` variant in `preferences.rs` (plus `Settings::is_set` so its reset button shows). Editors get
  per-file options from `Editor::apply_settings`; never read `settings.json` directly.
- **Key bindings:** only in `keymap.rs` (macOS variant on mac, Windows/Linux elsewhere;
  `secondary` = ⌘/Ctrl). A new action gets a shortcut in each base keymap that has one (in
  `common` only if every editor agrees); the test checks for conflicts and essentials, and
  JetBrains is the default. Editor-only bindings use context
  `"Editor"`; deeper contexts win. User bindings from `keymap.json` are installed after the defaults
  by `keymap::install` and tagged `USER_BINDING` so `binding_label` shows them. In the
  `"Terminal"` context, global non-⌘ shortcuts are bound to `NoAction` (`terminal_passthrough`)
  so keys reach the shell; add an action to its `KEEP` list to keep it working there. New user-facing actions go into `action_entries()` so Find
  Action / Search Everywhere list them, and shortcuts shown in UI come from
  `ui::binding_label`, never hard-coded strings.
- **Colors:** never hard-code; use `Theme::get(cx)`. Adding a color means: field in `Theme`,
  entry in the `color_keys!` macro, a value in **every** `assets/themes/*.json` (a test fails
  if a built-in theme misses a key), and a `docs/themes.md` key-table update.
- **Icons:** Google's Material Symbols (Apache 2.0), Rounded style, filled, 24px optical size, unchanged
  (`viewBox="0 -960 960 960"`, black fill — GPUI uses them as masks); fetch one from
  `fonts.gstatic.com/s/i/short-term/release/materialsymbolsrounded/<name>/fill1/24px.svg`. Files keep Kuana's
  semantic names (`folder-search.svg` holds `folder_open`). To add one: put `name.svg` in `assets/icons/`, add it to the
  `icons![]` list, the `Icon` enum and `Icon::path` in `assets.rs`. Remove unused icons.
- **File-type icons** come from `ui::file_icon` / `ui::folder_icon` (Charmed Icons, keeping their own colors, unlike the masked UI icons); don't duplicate name→icon matches. To update the pack, copy its `icons/base` → `dark/`, `icons/light` → `light/`, `icon_themes/base-theme.json` → `charmed.json` and adjust the `file_icons![]` list (a test checks it).
- **Adding a language:** prefer an extension (see `extensions.rs`); built in, it's a `Language` variant + `from_path`/`name`/comment tokens in
  `syntax.rs`, grammar + highlight `LangConfig` (+ capture-name mapping if its queries use new
  names), lint dispatch in `lint/mod.rs`, `ui::file_icon`, status-bar label in `workspace.rs`.
- **Rounded borders without a fill:** give the element a clear background *of the border's own color*
  (`color.alpha(0.)`), not none/`transparent_black`: GPUI blends a curved border's inner edge toward the
  background color, so black darkens the curves (visible on light themes; see `tab_shape`, `paint_tab_foot`).
- **Full-width rows:** `uniform_list` rows must be `w_full()` (wrap in a padded `w_full` div
  for inset highlights) or hover/click only covers the text. Inside auto-sized containers
  (popovers via `anchored()`, menus) `w_full()` collapses to the content width; there, rely on
  a flex column's default stretch instead (see `context_menu.rs`).
- **Git** always goes through `git::run` (no terminal prompts: `GIT_TERMINAL_PROMPT=0`; SSH
  `BatchMode` unless asking: inside `git::asking`, which `perform_git` and the clone dialog use,
  commands get `askpass::env` so Git and SSH ask through Kuana's dialog). Destructive operations (rollback, delete) always ask for confirmation first;
  deletes go to the Trash via the `trash` crate.
- **Persistence:** preferences in `settings.json` (theme, fonts, indentation…), key bindings in `keymap.json`, UI state in `state.json`, user themes
  in `themes/`, files' earlier versions in `local_history/`, all under `config_dir()` = `~/.config/kuana` (`$XDG_CONFIG_HOME/kuana`,
  `%APPDATA%\kuana`). `state.json` is written on panel toggles, resize end and folder changes.
- Comments explain *why*; match the surrounding density. Module docs use `//!`.

## Design preferences (from the user)

- JetBrains-like behavior and shortcuts. Compact, simple, modern UI that doesn't look like a stock GPUI app.
- **Visual effects** (`visual_effects`: `VisualEffects` Full (default) / Reduced / Minimal, one dropdown in
  Preferences → Appearance → Effects; levels, not separate switches, so options can't contradict each other).
  Each level drops one more kind of effect: Reduced → no gradients, Minimal → also no shadows, glows or
  animations. Read it with `Settings::visual_effects()` (it maps the older `reduce_visual_effects: true` to
  Minimal) and write it with `Settings::set_visual_effects` (removes the older key). It reaches drawing code as
  `Theme::gradients` / `Theme::reduce_effects` (set in `theme::apply_fonts`, so it survives theme switches):
  `ui::chrome_bg` and the project monogram check `gradients`; `ui::soft_shadow`, `focus_glow`, `glow` and
  transitions check `reduce_effects`. New effects must go through these helpers (no `shadow_lg()` & co., no
  hand-made `BoxShadow`, no unchecked gradient); a new kind of effect gets its place in the level order.
- **Transitions:** to animate a state change (focus, hover, on/off), style the element inside
  `with_transition` (`transition.rs`) from the progress, e.g. `mix(off, on, t)` for colors and `ui::faded`
  for glows; don't keep timers or animation state in views. A text field's border + glow is always `ui::focus_ring`. For an animated hover, use `.hover_bg`/`.hover_fill` on buttons (`with_hover_transition` for anything else) (`.row_hover` for list rows; a selected row's own fill wins) instead of `.hover()`. Text-color hovers stay plain `.hover()`. Things that come and go (toasts) use `.appear()` and stay until their exit has played. Progress text for an operation goes through `busy::Busy` (delay, then a minimum), never shown and hidden directly.
- **Islands layout** (helpers in `ui.rs`: `island`, `chrome_bg`, `popover`, `modal_panel`, `dock`/`segment_on`,
  `focus_glow`, `soft_shadow`, `island_edge`, `focused_edge`; use them for any new window, never ad-hoc borders/shadows): the sidebar, each pane and each bottom panel are rounded cards
  (`theme.background`, `ISLAND_RADIUS`, soft shadow) floating on the chrome (`theme.panel`, faintly accent-lit from the
  top) with `GAP` between them; resize handles fill the gaps. Keep dark themes calm: every edge between chrome and
  island costs attention, so a dark theme's chrome is held within `theme::MAX_CHROME_STEP` (2.5 L*) of its islands
  (`cap_chrome_step`, when themes resolve), islands keep a clear outline at every effects level (`island_edge`: `border` at 60%, since the chrome is
  too close in color to mark where an island ends) and a light shadow (dark depth 1 = 0.12; popovers and
  modals keep more), the chrome's accent tint is 2%, and the focused split is a hint of the accent (`focused_edge`). Content masks are square, so islands keep an
  `ISLAND_INSET` padding for children that paint their own background. Editor and terminal tabs are browser-like (`render_tab_bar`, `render_terminal_group`; shared `tab_shape`, `fit_tabs`, `measure_tab_names`, `tab_label`): a strip on the chrome above each pane's island
  (`TAB_STRIP_HEIGHT`, never scrolled: `fit_tabs` gives natural widths (names measured with `shape_line`), else only the widest shrink to a shared limit, else the current tab named and the others compact (no close button, icon + the start of the name, `TabSlot::Compact`), else icons, else the farthest in a "⋯ N" overflow menu; along the window's top `TAB_DRAG_ROOM` stays free after them to move the window), inactive tabs plain with hairline separators, on hover the same tab shape (borderless, between chrome and island colors; right after the current tab it repaints the current tab's foot on top, since tabs paint left to right), the current one island-colored, overlapping the
  island's top border and joined to it by concave feet (a thick ring clipped to a square, since GPUI can't clip to curves); the current tab's fill, outline and feet are painted in a `canvas` from one set of device-pixel-snapped coordinates (`paint_tab_foot`), since separately laid-out elements round apart at fractional positions (splits); it also covers a pixel past its bottom (the view tab: past its island side), since at fractional scales (150%) the island's 1px border is 1.5 device pixels and half a row of it would show under the tab (`tab_strip` makes the strips a pixel taller so their clip keeps that); there's no title bar row: the window's top row is the top panes' tab strips, with the title bar's lead (traffic lights / app menu; `render_title_lead`) and trail (run widget, window buttons; `render_title_trail`) laid over its ends; each notes where it ends (`track_title_end` → `Workspace::title_ends`, a change notifies after the frame) and a top pane's strip keeps its tabs clear of them (`PaneChrome::title_ends`, `TITLE_END_GAP`), so tabs start at their island (past the traffic lights when the sidebar is hidden); long names use `ellipsize` since GPUI's `truncate` keeps a flex row's full-width measurement.
  No full-width borders between areas. Modals (`modal_panel`) are chrome
  too, with long content (picker lists, Preferences pages, Find in Files) on an island inside; menus, completion, hover,
  toasts and tooltips are `popover`s. Selected rows: an `accent_soft` fill only (no edge bar or indicator); inputs are rounded with an accent
  border and `focus_glow` when focused; text buttons are pills.
- **UI style** (`ui_style`: `UiStyle` Modern (default) / Classic; Preferences → Appearance → Layout), reaching drawing
  code as `Theme::classic` (set in `theme::apply_fonts`, like the effects flags). Classic drops the islands for square
  areas side by side: the main row's background is the separator color (`ui::separator`: the outline made opaque, kept `MIN_SEPARATOR_STEP` from the areas and chrome) and the areas leave 1px gaps
  (plus 1px above and below) as the lines; tabs are rectangles (`classic_tab_shape`) as tall as their strip, whose room
  (`tab_room`) is chrome-colored with a bottom line the current tab covers. Window areas go through `ui::area`,
  `layout_gap`, `area_radius`/`area_inset`/`area_border` and the strip helpers in `workspace/tab_bar.rs`
  (`tab_strip_top`, `tab_strip_inset`, `strip_button_margin`), never `island`/`GAP`/`ISLAND_*` directly; pane tree math
  takes the gap as a parameter. Preferences' page and Welcome Setup follow it too (flush, `ui::separator` lines; Welcome Setup offers the choice); dialogs, pickers, menus and toasts float above the window and keep their rounded panels in both styles.
- Default theme **Ember** (`theme::DEFAULT_THEME`; charcoal islands on a darker chrome, `deep_chrome`; Ember Soft is the same on a lighter chrome). Clay Black / Clay Light stay the base that themes
  without `extends` fill missing colors from. Clay Black: near-black, *monochrome UI* (neutral grays, white accent) with a
  *colored* syntax palette and clear diagnostic colors — don't make code or lint colors gray.
- Minimal chrome: project and current branch in the tab row above the sidebar (`render_title_chips` in `render_sidebar_room`, beside the lead or trail laid over it, so they never push the tabs; while the sidebar is hidden they move into the title bar's lead, in the room they'd have above it (`lead_chips_room`) with the branch and Restricted Mode as their icons, and the top left pane's tabs start after them; so its tabs don't sit under the chips for the frame the sidebar shows or hides, the panes learn where the lead will end (`title_ends_now`) and the top left pane where it will start (`PaneChrome::left`, `editor_left`) before either is drawn), fitted to that room from their measured names (`fit_chips`: sync counts go first, then the branch's name shortens, then the branch is its icon, all while the project's stays whole, then the project's shortens; the monogram stays), as plain text that becomes a pill under the pointer (`CHIP_HEIGHT`: a compact 20pt pill, its name on the tabs' names' line, which hangs 15pt above the islands, so a taller pill or a resting fill would crowd them; the project's with a round monogram unless `project_avatar` is off, opens Recent Projects; the branch opens Branches…), branch name also in the Commit view's
  header; the title bar's trail holds only the window buttons (off macOS). The tools are on the activity bar (`workspace/activity_bar.rs`, `ACTIVITY_WIDTH`) on the sidebar's side
  under the tab row, as in VS Code: the sidebar's Files / Commit views as vertical tabs (`render_view_tab`; the
  current one, while the sidebar shows, is the editor's current tab turned on its side, `view_tab_shape`: island
  color, rounded on the far side a gap off the window's edge, outline and concave feet (`paint_concave`) joining the sidebar island's edge, painted after the island, which starts that
  side's edge light under it; its icon glides `VIEW_TAB_SHIFT` from the buttons' line to the tab's middle when selected, `area_joined` + `SideJoint` from `view_tab_joint`; a click on it hides the sidebar;
  Commit carries a change-count badge, without a ring: the chrome behind is a gradient); at its foot, apart from
  the tabs so none reads as one, groups (`Group`) between hairlines (Classic: separator lines across the bar): Run, Debug and, while anything runs, Stop for
  the last configuration (`run_tools`: Run and Stop `tint`ed green and red, the configuration in the tooltip, a
  right-click opens Run Configuration…), the bottom panels' toggles, then Search
  Everywhere, Extensions and Settings (`activity_tools`; in a short window `fit_tools` keeps them by
  priority and puts the rest in a More menu, reserving a separator only between groups that show; `activity_button`: built like a resting view tab, a row as tall as one with the icon in an
  `ACTIVITY_BUTTON` rounded square that fills on hover; an open panel or page in the accent on `accent_soft`; its measures come from `BarSize` (`FULL`, or `COMPACT` with `compact_activity_bar`: 40pt wide, the title bar's buttons' 30pt squares and 18pt icons; the workspace notes the width in `activity_width` for the sidebar's room); Classic view tabs are stacked rectangles, the open one edged with separator lines above and below (the first one's top is the tab row's line) and covering the bar's separator, like the current editor tab; every button centered on the bar, `ACTIVITY_WIDTH` = a button and a gap each side); `render_sidebar_block` lays out the bar and the island together. With `tools_location: "title_bar"` (`ToolsLocation`, `activity_bar::tools_in_title_bar`; Preferences → Appearance → Layout, Welcome Setup's Layout step with `layout_sketch`) there's no bar and the title bar is a row of its own again (`workspace/title_tools.rs`, `has_title_row`; not while Welcome Setup shows): traffic lights or app menu, the chips, then the same `activity_tools` (plus a sidebar toggle) as `bar_button`s fitted with `fit_tools` (the rest in More); the lead/trail overlays aren't drawn and no pane is `at_top`, so the tab row sits under it. The views are editor-like tabs (`tab_shape`) above the sidebar's island in that tab row (`workspace/sidebar_tabs.rs`, laid over `render_sidebar_block`'s top after the island; names dropped as it narrows: `fit_names`), `bar_room` is just the window edge's gap and, with the sidebar hidden, the sidebar's side has no block at all (`has_sidebar_block`). The status bar only shows status,
  no redundant labels or header rows.
- The sidebar docks left (default) or right of the editor area (`sidebar_dock`, `Workspace::sidebar_on_right`;
  Preferences → Appearance → Layout, the activity bar's right-click Move to Right / Left, Toggle Sidebar Position):
  on the right it renders after the editor column with the activity bar at the window's right edge (its view tabs
  mirrored), keeps its full height (the bottom panels stay under the editor), and its resize handle and drag
  direction flip.
- **Second sidebar** (`workspace/second_sidebar.rs`): a view (Files, Commit, Database, an extension's) can leave
  the sidebar for an island on the editor's other side (a view tab's right-click → Move to Right / Left Side,
  `open_view_menu`; `Workspace::moved_views`, `second_view` = the one open there, `second_width`, saved in
  `state.json` as `second_sidebar_*`). A view is in one place: ask `view_shown(mode)` / `set_view_shown`, never
  `show_sidebar && sidebar_mode == …`; `sidebar_views()` are the sidebar's own (at least one built-in stays,
  `can_move`), `sidebar_mode` is always one of them. A moved view keeps its activity bar tab as a button (lit
  while it shows there; with the tools in the title bar its tab leaves the strip and a Second Sidebar tool
  appears). It has no tabs, whatever it holds: the row above it stays free to move
  the window (and for the window's buttons on Windows and Linux). Its island starts with a header: the view's
  name (alone, the Commit view's toolbar instead; with other views there the name opens their list,
  `open_second_views_menu`, the way to switch without the activity bar), then Move Back and Close. The sidebar leaves it
  `second_reserve`; in a window too narrow for both it isn't drawn (`second_shown`). Views can't be stacked
  one under another yet. An extension view that shows without its entity (restored from the last session, in
  either sidebar) gets it in `make_shown_extension_views` (from `render`). View tabs carry no tooltip while a
  context menu is open: a right-click's opens under the pointer.

  Problems, Find, Git log, Debug, Database, extensions' output) or `ui::view_header()` (the sidebars' views: the
  Commit toolbar, Database, an extension's view, the tree's speed search, the second sidebar's header):
  `PANEL_HEADER` (32pt) tall, content centered, an 11pt semibold muted title in capitals, 24–26pt buttons, the
  close button last. No line under it and no margin after it: with the island's inset above and a line below, the
  row read as off-center. Never build a header row by hand.
- Rows and menu items are full-width hover targets; menus are compact (24px rows).
- Every scrolling list or pane gets an overlay scrollbar: give it a scroll handle (`track_scroll`), put it in a

  `uniform_list`). Thumbs show while scrolling, hovered or dragged, fade out a second later (`ScrollbarFade`,
  shared with the editor, whose track markers stay), and take the arrow cursor.
- Persist anything a user arranges (sizes, open panels, last project).
- **Small windows** (down to `window_min_size`, 480×320): the saved sidebar width and bottom panel height are shown
  smaller when the window can't spare them (`shown_sidebar_width`: the editor keeps `MIN_PANE_WIDTH`;
  `shown_panel_height`: it keeps `EDITOR_MIN_HEIGHT`; `viewport` is noted each render) and come back as it grows;
  the status bar drops items by width (`StatusFit`), the trail its run label and Debug (`BarFit`), the activity bar
  tools by height, and a tab strip narrows even its current tab (`fit_tabs`). Check new chrome at 480×320 too.

## Testing and verifying UI

- Prefer unit tests for logic (see `lint/*`, `search.rs`, `git.rs` real-repo test in a temp
  dir, `theme.rs`, `document.rs`). Run `cargo test` before finishing.
- To check UI, run the release binary with an isolated config:
  `XDG_CONFIG_HOME=<scratch>/cfg ./target/release/kuana <folder> <file>` — never let tests write to
  the user's `~/.config/kuana`. Screenshot only that window (`screencapture -l <windowid>`, find
  the id by **PID**, not by app name).
- Synthetic input (`osascript` keystrokes, CGEvent clicks) needs the window frontmost, paced
  ~0.3s per key, and a frontmost check before each key so nothing types into other apps.
- **Several Claude sessions may work in this folder at once** and run their own `kuana`
  instances. Never `pkill kuana`; kill by PID. Avoid synthetic input while another session is
  driving a window. Re-read files right before editing them; they may have changed.

## Known gaps

- Windows/Linux builds are barely tested (DirectWrite, keymap). Windows title bar: GPUI asks the app for `WindowControlArea`s on `WM_NCHITTEST` and lets the system drag/maximize only when no GPUI listener handled the mouse down, so the title bar's lead lies on an occluded `Drag` area of its own size (the root's focus-on-click would count) with its buttons occluded in front of it, the trail is `occlude`d, and the top panes' strips make their top padding and ends `Drag` (the first area in paint order that's under the pointer wins, so a `Drag` parent of unoccluded buttons would swallow them). The installer is Inno Setup (`scripts/kuana.iss`), built in the release workflow.
- `vendor/taffy` is taffy 0.9.0 (GPUI 0.2.2 pins it) patched in via `[patch.crates-io]`: its cache never reuses a final
  layout, since 0.9 could leave a text field at its minimum width at some window widths (Settings → Extensions, Windows).
  When a GPUI release uses a taffy that fixes this, switch to it and delete the copy and the patch (Cargo only warns
  "patch was not used" once GPUI moves past 0.9.0).
- ESLint only via CLI on open/save.
- LSP: no semantic tokens; per-language server ordering/disabling by id isn't there yet (only `language_servers`). No Emmet.
- Git: the log loads the latest 3000 commits; history edits are reword / squash / drop (`git::edit_history`), no reordering or splitting.
- The release binary (`--release`, unstripped) is ~61 MB, largely rumdl (pulls a second oxc, clap, allocators), grammars and
  wasmtime (Cranelift for grammars; components and WASI for extensions' code add ~5 MB stripped).
